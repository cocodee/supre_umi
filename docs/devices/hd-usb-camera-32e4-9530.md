# HD USB Camera（USB 32e4:9530）

> 采集日期：2026-10-16。以下信息来自目标机器的 V4L2、USB 描述符及实际取流验证。标称能力与实测结果分别标注。

## 设备概况

| 项目 | 设备报告或验证结果 |
| --- | --- |
| 设备名称 | `HD USB Camera: HD USB Camera` |
| USB 标识 | Vendor ID `32e4`，Product ID `9530` |
| 设备序列号 | `2020042508` |
| 接口与驱动 | USB 2.0 摄像头；Linux `uvcvideo` 驱动 |
| 当前 USB 链路 | 480 Mbit/s（链路标称速率，非实际视频吞吐量） |
| 视频采集节点 | `/dev/video0` |
| 元数据节点 | `/dev/video1`，输出 UVC 载荷头元数据，不能作为视频画面使用 |
| 媒体控制节点 | `/dev/media0` |
| 当前视频配置 | MJPEG、640 × 480；驱动报告 30 fps |
| 实际验证 | 已从 `/dev/video0` 成功读取 640 × 480 帧，并通过预览程序输出 JPEG 抓拍和实时视频流 |

设备名称只是 USB 描述符中的通用名称，目前无法据此确认品牌、具体商业型号、传感器型号或镜头参数。程序中建议使用以下稳定的设备路径：

```text
/dev/v4l/by-id/usb-HD_USB_Camera_HD_USB_Camera_2020042508-video-index0
```

它目前指向 `/dev/video0`；相比直接写死 `/dev/video0`，重新插拔或设备枚举顺序变化时更稳妥。

## 驱动报告的视频模式

下表是摄像头向 V4L2 声明的模式，**不是逐项实测帧率**。驱动列表中重复出现的 1600 × 1200 档位已合并。

| 分辨率 | MJPEG 标称帧率 | YUYV 4:2:2 标称帧率 |
| --- | ---: | ---: |
| 640 × 480 | 30 fps | 30 fps |
| 800 × 600 | 30 fps | 20 fps |
| 1024 × 768 | 30 fps | 10 fps |
| 1280 × 720 | 30 fps | 5 fps |
| 1280 × 1024 | 15 fps | 9 fps |
| 1600 × 1200 | 15 fps | 5 fps |
| 1920 × 1080 | 30 fps | 5 fps |
| 2048 × 1536 | 15 fps | 4 fps |
| 2592 × 1944 | 15 fps | 3 fps |

MJPEG 是设备输出的压缩格式；YUYV 是未压缩的 YUV 4:2:2 格式。若设计目标是较高分辨率和帧率，驱动报告的 MJPEG 模式更合适，但仍应在目标工作负载下测量实际帧率、延迟和画质。

## 可调参数

设备提供亮度、对比度、饱和度、色调、伽马、增益、锐度、背光补偿及工频防闪烁控制。当前工频设置为 **50 Hz**，自动白平衡已开启。曝光处于驱动标记的 **Aperture Priority Mode**，动态帧率已开启；因此白平衡色温和手动曝光时间当前显示为不可调状态。若应用需要固定曝光或跨帧稳定亮度，应单独设计控制策略并验证实际效果。

## 集成注意事项

预览程序打开视频流时会占用 `/dev/video0`。本次尝试逐档实测时，设备正被预览服务使用，新的采集进程无法打开摄像头，因此目前**只有 640 × 480 取帧经过实测**，表中其他档位仅为设备声明的能力。设备没有报告视场角、焦距、畸变参数、硬件时间同步精度等信息；若用于机器人视觉或测量，这些参数需要另行标定和测试。
