# UMI 夹爪宽度传感器：AS5600 磁编码器

> 现场检查时间：2026-10-16，目标机器本地时间 UTC+08:00。机械装配与 80 mm 行程来自项目设计说明；USB/I²C 连接及寄存器读数由目标机器验证。

## 用途与信号链

UMI 夹爪上装配 AS5600 磁编码器和纵向磁铁，用磁编码器读数估计夹爪开口宽度，替代 UMI 原版使用 ArUco 视觉标记检测夹爪宽度的方案。本传感器只提供磁角度观测；夹爪宽度需要通过机械传动关系和标定参数计算。它不负责 Vive Tracker 或夹爪在空间中的位姿定位。

```text
夹爪机构运动 → 磁铁与 AS5600 的相对角度变化
             → AS5600 12 位角度读数
             → I²C 总线
             → CH341 USB 转 I²C 控制器
             → Linux /dev/i2c-13
             → 夹爪宽度标定与应用程序
```

总线号 `13`、USB Device 编号和路径是本次枚举结果，设备重新插拔或系统配置变化后可能改变。程序启动时应通过 `i2cdetect -l` 或 `/sys/class/i2c-adapter/*/name` 找到名称为 `ch34x-mphsi-i2c` 的适配器，再访问地址 `0x36`；不要把总线号 `13` 当成永久硬件标识。

`0x36` 是 [AS5600 官方数据手册](https://look.ams-osram.com/m/7059eac7531a86fd/original/AS5600-DS000365.pdf)规定的 I²C 从设备地址。本机在该地址获得与 AS5600 寄存器布局一致的只读响应；USB 枚举显示的是 CH341 控制器，AS5600 本身不会单独出现在 `lsusb` 中。

## 编码器与本次只读检查

AS5600 是 12 位磁角度传感器，一个完整电气周期有 `0–4095` 共 4096 个计数。每计数对应的角度为 `360° / 4096 = 0.087890625°`。相关只读寄存器见[官方寄存器表](https://look.ams-osram.com/m/7059eac7531a86fd/original/AS5600-DS000365.pdf)：

| 寄存器 | 用途 | 本次读数 |
| --- | --- | --- |
| `0x0B` STATUS | 磁铁检测及磁场强弱标志 | `0x67`；其中 `MD=1`、`ML=0`、`MH=0`，表示本次检查检测到磁铁，未报告磁场过弱或过强。 |
| `0x0C–0x0D` RAW ANGLE | 12 位原始角度，高字节仅低 4 位有效 | `0x0A 0x0D`，合成为 `0xA0D = 2573` 计数，约 `226.14°`。 |
| `0x1A` AGC | 自动增益控制读数 | `0x60`，十进制 96。 |
| `0x1B–0x1C` MAGNITUDE | 磁场幅值相关读数 | `0x08 0x39`，合成为 `0x839 = 2105`。 |

上述数值只代表检查瞬间的状态，**不能直接解释为夹爪宽度，也不能证明 80 mm 全行程的线性、重复性或绝对精度**。`MD`、`ML`、`MH` 只按数据手册定义的位解释；STATUS 中其他位没有在本次检查中用于判定。

## 宽度换算与标定

若设计假定夹爪 **80 mm 全行程恰好对应 AS5600 的完整 4096 计数周期**，理论量化步距为：

```text
80 mm / 4096 = 0.01953125 mm/计数 ≈ 0.02 mm/计数
```

这个数值是**理想换算条件下的量化步距，不是实测宽度精度**。若夹爪全行程实际只跨越 `N` 个计数，则步距应改为 `80 / N` mm/计数。机构间隙、磁铁偏心、装配误差、传动非线性和读数噪声都可能使实际误差大于一个计数。

建议在夹爪完全闭合和达到已知开口宽度时分别记录 `r_closed` 与 `r_open`，先处理 `4095 → 0` 的环绕并确定开合方向，再计算：

```text
width_mm = measured_span_mm × (r_unwrapped - r_closed) / (r_open - r_closed)
```

其中 `measured_span_mm` 应由实测端点宽度给出；若标定全行程确为 80 mm，才取 80。端点间的计数差必须使用展开后的角度值。若机构的宽度与磁角度并非线性关系，应使用多点标定曲线或查表，并在工作范围内验证误差。上电后单圈绝对角度可以读取，但如果运动可能跨越零点或超过一圈，应用还需定义展开和复位策略。

## 检查命令

```bash
# 找到 CH341 与其 I²C 适配器
lsusb -d 1a86:5512
i2cdetect -l

# 以下示例中的 13 是 2026-10-16 的总线号；使用前重新核对
sudo i2cdetect -y 13
sudo i2cget -y 13 0x36 0x0b b
sudo i2ctransfer -y 13 w1@0x36 0x0c r2
sudo i2cget -y 13 0x36 0x1a b
sudo i2ctransfer -y 13 w1@0x36 0x1b r2
```

读原始角度时，将返回的两个字节按 `((high & 0x0F) << 8) | low` 组合。以上仅使用只读检查；当前方案不要求修改 AS5600 配置或烧录 OTP。

## 2026-10-27 复验

复核时机器本地时间 UTC+08:00，内核 `6.1.59-rt16`。与旧记录相比有两点变化，以及一项新发现的传感器现象。

### 总线号已变化

CH341 仍在 `lsusb` 中（`1a86:5512`，本次为 Bus 001 Device 004），`ch34x_mphsi_master`
已加载，但适配器现在是 **`i2c-3`**（`ch34x-mphsi-i2c at bus 001 device 004`）。旧文档记录的
`i2c-13` 此时对应显卡 DP AUX 总线（`AUX A/DDI A/PHY A`），并非 CH341。这再次说明总线号不能
硬编码；复验工具改为按适配器名 `ch34x-mphsi-i2c` 查找，见
[`umi_devices/`](../../umi_devices/)。

### 只读寄存器

`0x36` 有应答。本次读数为：

| 寄存器 | 本次读数 | 说明 |
| --- | --- | --- |
| `0x0B` STATUS | `0x67` | `MD=1`、`ML=0`、`MH=0`，检测到磁铁，未报强弱异常 |
| `0x01` ZPOS | `0x0000` | 未编程 |
| `0x03` MPOS | `0x0000` | 未编程 |
| `0x07` CONF | `0x00` | 默认值，未做滤波/低功耗等配置 |
| `0x1A` AGC | 约 `97` | 读数稳定 |
| `0x1B` MAGNITUDE | 约 `2108`–`2111` | 读数稳定 |

配置寄存器均为默认值，说明芯片未做过零点/量程或滤波设置；RAW ANGLE 与 ANGLE 输出一致
（ANGLE 不是经 ZPOS/MPOS 变换后的结果）。

### 新发现：静止时角度以约 50 Hz 摆动

夹爪保持静止时，连续读取 `0x0C–0x0D`（RAW ANGLE）与 `0x0E–0x0F`（ANGLE）：

- 两路读数**同步**在约 `1467` 与 `2628` 计数之间往复，跨度约 `1088` 计数（约 `96°`）；
- 摆动是平滑连续的（每步约 `72.6` 计数，即 17 个量化级），不是随机跳变；
- 以过零法估计周期约 `19.9 ms`，即 **~50.3 Hz**；
- 同期 AGC 与 MAGNITUDE 基本不变。

该现象**不是读取错误**：用标准 `i2ctransfer` 命令重复读取得到同样的抖动，而 STATUS、
MAGNITUDE、ZPOS 等寄存器完全稳定，说明 I²C 传输本身可靠，摆动来自 AS5600 报告的角度本身。

由于磁场总幅值稳定而计算出的角度却摆动约 96°，且单个刚性静止的磁铁不应产生这种变化，
可能原因包括：磁铁或传感器安装松动/被 50 Hz 机械振动激励、磁铁磁化方向与安装几何不匹配
（如轴向充磁使面内磁场很弱，角度解算病态），或附近存在 50 Hz 交变磁场。**来源尚未确认。**

影响与建议：

1. 单次瞬时读数不能直接当作夹爪宽度。采集时应做时间平均或同步采样；复验工具
   `umi_status.py` 默认多次取均值并输出 `raw_angle_span` 以暴露抖动幅度。
2. 标定前先排除硬件原因：确认磁铁为数据手册要求的径向(diametric)充磁、固定牢靠、与
   芯片气隙在推荐范围，并远离大功率 50 Hz 设备；随后重测静止跨度应远小于 1 个计数级。
3. 若抖动确为工频干扰，需要在采集端做 50 Hz 陷波或同步平均，并验证其对动态宽度的影响。

### 读取速率与权限

- 单次 2 字节组合传输约 `0.82 ms`（约 `1.2 kHz` 上限），远高于 50 Hz 目标采样率；
  速率不是瓶颈，瓶颈是上述角度抖动。
- `/dev/i2c-*` 为 `root:i2c`、`0660`，用户 `zy` 原先不在 `i2c` 组。本次已将 `zy` 加入
  `i2c` 组（`sudo usermod -aG i2c zy`），重新登录后生效；当前会话用 `sg i2c -c` 验证。

### 宽度换算

两点标定换算按未展开计数计算，公式与旧文一致：

```text
width_mm = span_mm × (r_unwrapped − r_closed) / (r_open − r_closed)
```

工具 `gripper_as5600.py --calib CLOSED,OPEN,SPAN_MM` 实现该式，按较短弧处理 `4095→0`
环绕（假定行程小于半圈）。该换算在抖动问题解决前只能得到受噪声污染的宽度。

## 2026-10-29 复测：50 Hz 波形与滤波

以约 274 Hz 连续采样 5–17 s（与 Web 服务并发读取），对 RAW/ANGLE 做解绕和 FFT：

| 项目 | 实测 |
| --- | --- |
| 原始角峰峰值 | 1086–1158 counts（约 21–23 mm 理论宽度） |
| 主频 | ~50.0 Hz（49.7–50.4 Hz 簇），另有约 100 Hz 谐波 |
| 50 Hz 正弦拟合 | 幅度约 508 counts，R²≈0.87，残差 std≈144 counts |
| AGC | 恒为 95 |
| MAGNITUDE | 2074–2078（±2 counts） |
| STATUS | 恒为 0x67（MD=1，ML=MH=0） |
| 波形形状 | 顶部在 2627 counts 处有明显平顶（约 10% 周期），底部在 1469–1686 之间变化；均值 2266、 中位数 2410、极值中点 2048 counts |

关键推断：

- 磁场总幅值与 AGC 稳定，说明磁铁到芯片的距离/充磁强度没有明显变化；抖动来自**角度解算
  的扰动**，不是夹爪机构真实运动。
- 顶部平顶且极值中点为 2048 counts（理论 40.00 mm），而均值/中位数为 44.3/47.1 mm，
  说明波形**不对称**；直接用均值会把宽度估计得偏高，且平均窗口长度不同会得到不同结果。
- 50 Hz 成分在两种不同采样率（约 274 Hz 与 363 Hz）下都接近 50.0 Hz，排除了固定采样率
  对高频分量的简单混叠；更像真实的工频磁场/机械激励。
- 之前 16 个样本的均值在 I2C 实际 120–270 Hz 时只有 60–130 ms，且采样相位与 50 Hz
  稀疏重复，静止宽度仍有约 6.3 mm 峰峰抖动。

软件处理（已落地）：

- AS5600 采样默认不限速（实际约 300–400 Hz），避免 50 Hz 与低采样率锁相；
- 宽度使用最近 **0.25 s 时间窗**的环形均值（CLI 与 Web 共用）；
- 标定采样改为 100 点、不限速，避免 `--hz 50` 与工频锁相；
- 复测 Web 静止宽度峰峰约 **1.0–1.6 mm**（std 0.24–0.30 mm），CLI `GripperStream`
  约 **1.0 mm**（std 0.24 mm）。

仍未解决：绝对宽度标定、顶部平顶的硬件原因。建议下一步：

1. 确认磁铁为径向充磁、固定牢靠、与芯片同轴且气隙在推荐范围；检查磁铁是否可能在支架内
   微动（即使夹爪本体不动）。
2. 把整套夹爪移离电源适配器/变压器/电机/风扇等 50 Hz 源，观察跨度是否减小；也可用电池
   或线性电源单独给 AS5600 供电。
3. 用第二片 AS5600 + 第二块 CH341 做差分（`DualAs5600` / `wrap_diff`），共模 50 Hz
   应在差分信号中抵消；这是目前最可靠的硬件方向。
4. 若 50 Hz 始终存在，标定必须在**与采集相同的 0.25 s 时间窗滤波后**进行，并把标定
   样本与运行时滤波保持一致；绝对宽度不能直接用瞬时计数换算。
